## Summary

采用单机、单进程中转服务，使用 TypeScript、Node.js 24 LTS、官方钉钉 Stream SDK 和 SQLite。
平台收发、会话路由、Harness 适配、状态存储与出站调度分离。私聊会话绑定持久化，
每轮固定展示策略；运行中普通输入及时 steer，人工答复优先返回原请求。
输入接收、任务执行和逐条投递各有独立状态；网络结果未知时停止自动重放。

首个真实适配候选为桌面 WorkBuddy 本机 ACP，内部接口标明实验性。
当前版本已定位 steer 的接收与同轮消费静态路径，但尚未完成已登录真实验证。
核心模块先用测试用适配器验证；真实适配实现与支持声明必须以 V-01 至 V-05 的对应证据为前提。
本功能不包含外部事件触发、群聊、第二个真实 Harness、Agent 执行器、远端部署或应用发布。

## Technical Context

**Language/Version**：TypeScript 严格模式（选型基线 5.5 或以上）、Node.js 24 LTS、npm；
实现时固定兼容的精确版本和 lockfile，不宣称 Node 24 为最新 LTS。

**Primary Dependencies**：`dingtalk-stream`、`better-sqlite3`、Zod 4；
Harness JSON-RPC/HTTP/SSE 位于实验适配器内，使用 Node 网络能力。
不引入 ORM、Web 框架、外部消息代理或模型 SDK。

**Storage**：本地 SQLite，实际内嵌引擎 ≥3.51.3，WAL、FULL、外键、单写入连接；
会话映射、入站输入、操作尝试、任务、人工请求、逻辑输出及 outbox 同库保存。
数据库和敏感能力存储置于 Git 外的配置目录，不支持网络文件系统。

**Testing**：Node 内置测试运行器；确定性测试 Harness、测试平台、虚拟时钟与崩溃注入；
真实平台验收单独记录，不能以模拟通过替代。当前无应用构建或测试命令。

**Target Platform**：Linux，与桌面 Harness 同机；目前只研究 WorkBuddy 5.6.2 / CLI 2.147.0。
这不是固定安装要求，升级须重新匹配能力证据。

**Project Type**：常驻消息中转进程和本地 CLI，无公网管理接口或 Web 前端。

**Performance Goals**：满足 SC-001 至 SC-009；测试用 Harness 在受控执行屏障下，
两条新输入均在原任务完成前实际生效。ACK 不等待 Harness 完成；锁和数据库事务不跨网络等待。
真实“及时”以当前任务内生效及后续工作变化判定，记录实际时间，不虚构毫秒 SLA。

**Constraints**：只处理文本私聊；不建立普通输入排队回退，不自动授权、取消、抢占或替换会话；
单条明确失败投递最多三次尝试，未知结果不盲目重试；输出类型不能从正文猜测；
平台限额必须有对应证据，正常接收/steer 不额外发状态提示。

**Scale/Scope**：单应用实例、单进程、单数据库；至少覆盖两个独立私聊及同轮多输入、多输出。
不承诺多机、高可用或执行中任务全面无损恢复。通过二次启动排他检查防止同库多进程消费。

研究前未知项为运行栈、持久方案、平台传输、真实 Harness 接口及用户交互形式；
对应决策见 [research.md](research.md) R-01 至 R-10。
真实能力证据缺口已经转为具名准入检查，不作为待用户猜测的产品需求。

## 关键流程与并发边界

1. 平台适配器校验应用范围与私聊类型，群消息仅 ACK 并丢弃；有效私聊以可靠标识事务登记，
   再 ACK。重投返回原记录，不重复产生任务或限制提示。
2. 路由先识别显式人工答复，再判断首轮、后续轮或运行中 steer。
   首次绑定通过唯一约束预留；创建结果未知时保留预留，不重复建会话。
3. 短会话临界区仅用于核对绑定、活动任务、请求有效性与登记转交意图；
   网络提交和整轮输出不持锁。首轮返回任务关联前的新输入遇到真实阻塞时明确失败，不暗中排队。
4. 适配器快速返回 accepted/rejected/unknown；执行事件持续独立接收。
   steer 携带原任务标识；完成竞态的拒绝不能自动改作下一轮。
   已确认人工答复优先于尚未提交的普通输入；不撤回已在途调用。
5. 一个短事务中处理控制事件、消息片段及展示决定；完整且选中的逻辑消息产生 outbox。
   即使全隐藏，执行终态、人工输入和错误处理仍运行。
   人工请求另须保存 sourceMessageId，正文完整且该映射落盘后才生成唯一的请求正文投递；
   请求与正文到达顺序不影响持久关联和重启恢复。
6. 每个私聊独立出站；明确临时失败按预算先处理，终态失败后继续并记录缺失；
   unknown 暂停该私聊后续发送并核实，不阻塞其他私聊或 Harness 输入控制。
7. 重启恢复原绑定和已完成任务；在途外部调用标记 unknown。
   未转交的旧普通输入标记恢复中断，不自动扫描重放。
   原会话不可读、不可续接或登录失效时明确报告，保留原关联。
