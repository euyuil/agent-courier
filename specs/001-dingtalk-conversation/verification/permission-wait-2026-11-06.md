# 执行权限等待期间的补充输入探测

日期：2026-11-06。已登录桌面 WorkBuddy 5.6.2；正常当前运行元数据确认 CLI 2.147.0。

## 实现

新增显式 --acp-automatic-permission-steer 入口，使用生产自动连接工厂、私有 SQLite、独立用户 Harness 会话 A 和正常配置的纯 MCP 格式化来源。探测目录内单独声明 Bash ask 规则；不改变全局配置。只有实际 A 的正常配置接口明确报告 default，才允许提交受控执行权限任务。

探测要求原 Bash 权限待答时连续提交两条补充，各自产生一个有准确原生身份、完成回显、精确注入证明及归一化快照的不同进度输出。两个实际输出须早于拒绝决定，原权限在派发时仍有效。结束时仅拒绝已匹配的原 Bash 请求，核对明确接收及原 Run 取消。接收回执不能替代实际效果；unknown 不重试，不批准执行权限，不发送钉钉消息。

单次观察上限为 120 秒、4096 个原始帧/归一化事件、8 MiB 原始序列化内容及既有格式化正文边界。额外工具/权限、请求撤销、外来引用、正文或结果冲突、执行已完成、超时或截断均不能通过；回调在结束时恢复。报告只含有界计数、已知状态和匹配布尔值。

## 启动宿主的显式模式配置

私有自动连接配置新增可选 bootstrapPermissionMode，仅接受 default。它通过正常 session:create 请求空白启动宿主 H 的模式，并要求返回配置明确包含同值；请求已派发但未确认时保留 unknown，不再次创建。固定宿主/端点模式拒绝这个选项，避免静默忽略。

该声明进入私有宿主缓存及证据指纹；已缓存模式不匹配时拒绝采用，不删除原用户关联。它只说明启动宿主的配置请求，不能证明后来创建或恢复的 A/B 使用相同模式，也不改变或批准 A/B 中的权限请求。
