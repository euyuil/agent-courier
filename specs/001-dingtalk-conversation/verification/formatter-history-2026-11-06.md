## 历史模式的生产过滤缺口

安装 CLI 的 replayOffsetMeta/withReplayOffset 将 codebuddy.ai.mode=history 与 offset 写入元数据。此前 internalFrame 只过滤若干布尔历史字段，未覆盖这种实际表示；当其他关联字段看似属于当前 Run 时，历史内容可能被当成实时输入或工具更新。

两项生产契约回归先复现历史内容确认新 Run、旧格式化正文被投递，以及历史人工请求/权限撤销/steer 回显改变当前状态，再补齐参数、更新及内容三层元数据上的 history 模式过滤。flat 和 nested 厂商元数据均识别；正常 ask 模式和无历史标记的实时输入继续处理。没有根据正文、到达次序或相同文本猜测历史，offset 也不作为实时消息/片段身份。

## 正式观察入口与步骤

新增 --acp-bootstrap-owned-formatter-history，与其他独立任务模式互斥，使用同一正常输出配置构造器。前置独立创建、断连/load 及两轮普通上下文通过后：

1. 验证原 Run 两条同文 progress 和一条 final 的三个原生工具、结果回显、完整快照及独立 end_turn。
2. 只有上述通过，才正常断开自己的 ACP 连接。保留原 Harness 运行进程，不调用桌面 destroy、不新建替代 Harness 会话。
3. 创建不同的适配器和 ACP 连接，只 load 同一个原 Harness 会话，观察原生历史和是否产生重复的归一化输出。
4. 明确接受 load 且无异常人工请求后，启动新 Run，请其只格式化上一轮 final；新输入不包含旧正文或标记。
5. 分别核对原工具 ID/完成结果和显式历史来源、新 Run 的原生来源/完整快照/独立终态、原上下文复现，以及新工具未复用旧逻辑身份。

原始记录限制为 4096 帧/事件及 8 MiB；源任务或恢复未知即停止，不重试或创建替代目标，也不回答或批准任何人工请求。内部观察对象只用于本次原生身份比较，不进入共享报告；共享结果仅含计数、已知状态和匹配布尔值。

loadSession 静态实现等待 replayHistory，后者逐条等待发送历史更新；这不自动保证跨 GET/POST HTTP 流的所有帧已经在客户端处理完毕。因此另记 load 返回后的历史帧数，代码未将 load 返回用作全局回放屏障。
