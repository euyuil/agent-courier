# 三个独立适配器进程的原上下文恢复

日期：2026-11-06。桌面 WorkBuddy 5.6.2；每轮均从正常当前运行注册元数据确认 CLI 2.147.0。

## 正式入口

新增 --acp-automatic-runtime，复用普通探测的显式启用、私有启动配置、Git 外结果文件和自有桌面进程清理。实现位于 tests/probes/workbuddy-runtime.ts；默认测试不运行此真实模式。

该模式直接调用生产连接工厂，不先在桌面启动宿主内执行用户任务。父进程串行启动三个独立 Node 子进程，只有正常退出且结果完整才继续；私有 SQLite、适配器映射、激活意图、宿主镜像证明和原用户上下文引用在各进程之间保留。子进程持有相同实例锁，正常关闭后释放。

1. seed：自动创建 H，创建不同的 A，执行一轮仅记住合成标记的任务。
2. reuse：第一个进程退出后，用新进程和原 SQLite 复用 H、load 原 A；续聊输入不重述标记。
3. replace：第二个进程退出后，父进程核对原 H 的身份、空闲、待处理和已持久 Run 归属，正常结束本次自有后端；内核身份确认原进程退出后，第三个进程自动新建 H2 并 load 原 A，再次续聊。

每个阶段只提交一次；unknown、非正常退出、复用进程身份、外来宿主、正文不符、工具调用、观察截断或旧进程状态不明均停止。不会回答问题、批准执行权限、抢写其他客户端或重放未知操作。子进程报告严格校验后只发布计数、版本和匹配布尔值；真实引用、进程身份和正文不进入共享结果。
