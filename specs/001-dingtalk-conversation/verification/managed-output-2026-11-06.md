## 自动后端的能力目标

自动独占组合为不同 Courier 会话启动不同后端，后端退出后也可能更换空白宿主。旧指纹使用临时 ACP 端点，因此同一配置的不同用户、重连及宿主替换会产生不同能力目标，无法稳定绑定验证证据。

回归先复现端点变化导致指纹变化，再将自动管理目标绑定配置的桌面连接地址。工作目录、正常配置的 CLI 版本、认证范围、独占/隔离策略、权限模式、输出模式及固定实现摘要继续进入指纹；变更任一相关条件仍使旧证据不匹配。手工固定连接及专用上下文连接仍绑定各自端点。每个后端的正常发现、原宿主归属、进程身份和版本核对均保留，不能仅凭配置地址接入任意后端。

三个进程实际正常退出；每轮原 A/B 的精确上下文、原 Run 及原生 end_turn 均匹配。正常结束自有空闲 A、确认旧进程退出后，新空白宿主恢复原 A；B 的原宿主/进程不变。跨三个进程及宿主替换的配置目标相同，原始指纹只用于私有进程通信，不进入公开摘要。该结果补充此前恢复观察，不等于 Courier 应用或平台链路验收。

## 不依赖格式化工具的两次问答与两条补充

新增 --acp-automatic-managed-question-steer，使用 acp-text 和内置 AskUserQuestion，保留相同的严格效果条件：第一题待答时提交两条独立补充，第一条要求第二题，第二条要求最终正文追加标记；两题各只答一次。一个已绑定原 Run 的普通可见消息须同时含原最终标记、两项选择和额外标记，且产生于两题对应原生完成结果之后、原 Run 终态之前。输入回显、历史、内部思考或不同消息的拼凑均不能通过，也不把普通文本宣称为带 final 类型。

真实样本共 402 帧：两条控制参数、明确接收回执、完整注入广播与拥有者证明均匹配；两次答案明确接收，原生工具结果分别出现在第 151、307 帧，均只含所选标签。原 Run 原生 end_turn，普通输出身份与正文匹配，但四项正文条件为 true/true/true/false，第二条补充的额外标记缺失。没有未知工具、执行权限请求、执行权限批准或钉钉发送，整体仍 unverified。

只读核对已安装代码显示：steer 缓冲按原拥有者保存各输入，注入时合并为下一次模型输入，并逐条保存历史及广播完整输入。这是实现路径的静态依据；运行中观察到广播不等于证明模型遵循全部要求。当前样本将缺标记问题收窄到不依赖格式化工具的原生任务链路，不能据此声称 Courier 已解决全部及时 steer 语义，也不重发、合并替代或改成新任务。

## 通用输出投影修复

真实格式化权限阻塞促使复核完整人工请求是否能到达用户。两项离线回归先失败，再修复 projectOutput：

- 早到且未完成的选中进度不能挡住已经完整、原映射已保存的问题/权限请求；仅显式用户答复才调用一次原 Run/原请求的 answer。
- 被策略隐藏或非用户可见的未完成输出不能挡住已完成的选中 final。普通选中消息之间仍按顺序投递；隐藏消息仍保持 assembling，任务终态仍只接受 Harness 的独立信号。

回归同时覆盖问题/权限、正文/请求的两种到达顺序及原上下文，不自动回答或补造消息完成。它们使用测试 Harness 和平台，不能充当真实钉钉往返。
