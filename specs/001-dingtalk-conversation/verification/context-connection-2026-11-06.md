# 实际 Harness 会话的专用 ACP 连接

日期：2026-11-06。桌面 WorkBuddy 5.6.2；当前正常运行注册元数据确认 CLI 2.147.0。

## 模式差异的定位

零 Agent 任务的冷启动样本确认：桌面返回的 H 配置为 default，但后端启动参数未采用该值，A 在 load 前后均未确认 default。并非只有预热进程存在这项差异。

当前安装代码的模式解析会忽略 craft/expert 场景中低于其场景默认值的权限声明；原生 setSessionConfigOption(mode) 又通过视图事件应用变更。管理连接先初始化 H、再新建或加载 A 时，视图当前对象在首次输入前仍可为 H，因而不能仅凭配置调用完成认定 A 已更新。

只读本地命令曾提供一个有界诊断：首个诊断请求因错误使用 UUIDv4 跟踪标识而被 -32602 明确拒绝、零帧；改用生产 UUIDv7 生成器后，只得到一帧固定终端提示，无用户任务、思考或工具，随后 A 的模式可回读为 default。该诊断帮助定位视图切换时点，生产组件使用下面的专用连接路径。

另一份零 Agent 任务样本正常关闭本次管理连接，让新 ACP 连接首次就 load 原 A。原 A 明确加载，default 模式回读通过，未新建 H、未执行本地命令或 Agent 任务，也没有抢占其他客户端。

## 已实现的工厂组件

connectWorkBuddy 增加内部 contextSessionRef 参数；它不是私有 JSON 的新字段。管理连接创建 A 后由调用方正常释放，再用该参数连接同一个 A：

- 连接前要求已确认的 H、仅作宿主的 H 标记及非空 Courier 归属；H、未知或外来上下文均拒绝。
- 上下文连接只能复用现有后端，不激活缺失或已结束的宿主；宿主生命周期仍由管理连接负责。
- initialize 后不再 session/new H，首次实际上下文操作为 load 原 A。该连接不能创建其他 Harness 会话、load 其他引用或在 load 完成前派发用户输入。
- 当配置声明 default 时，load 后核对原生 configOptions；必要时仅设置原 A 为 default，并要求准确回读。配置意图和结果独立持久化，unknown/dispatching 不重发。
- 后续原生 load 已明确报告当前 default 时，可以建立新的状态事实，不把先前结果未知的配置操作伪造为已确认。
- 不确定的重新加载撤销之前的可用状态；损坏配置记录不能授权新修改。其他客户端持有写入权时返回原冲突，不修改模式、关联或新建替代上下文。
- 上下文连接角色和新实现进入证据指纹；子连接不将自身声明为完整 createAndResume 能力，三项输出/人工能力继续 unverified。

这一组件及权限等待显式入口已接入。普通真实服务组合尚未自动按实际 A/B 分配和管理这些连接；不能据此开放真实 serve 或宣称全部生命周期已支持。

后续普通组合已接入连接管理，并按 Courier 会话隔离自动宿主/后端；更新实现与交错观察见 [managed-connections-2026-11-06.md](managed-connections-2026-11-06.md)。下文保留此阶段的权限等待样本及当时验证边界。

| 两条补充 | 各派发一次并明确接收 |
