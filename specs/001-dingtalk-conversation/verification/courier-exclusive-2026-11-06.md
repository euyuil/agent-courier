# Courier 独占 Harness 会话的实现与观察

日期：2026-11-06。桌面 WorkBuddy 5.6.2；采用操作者确认的独占方案。后续已按明确要求写入规格，FR-003/FR-009 原文保留，策略与条款对照见 ownership-decision-2026-11-06.md。

## 普通配置与适配器实现

私有连接 JSON 可显式配置 ownership={mode:courier-exclusive,bootstrapSessionRef:<H>}，必须同时提供 desktopDebugUrl；原显式 endpoint/cwd/cliVersion 和输出配置仍适用。

- connect 通过正常账户 API 与 session:get 核对已登录、准确 H/cwd、空闲、三类人工待处理均为空，且无用户/Agent/工具任务历史；不读取登录存储、令牌或进程凭据。
- H 在私有适配映射中登记为 courier_bootstrap，不能覆盖已有 Courier 用户归属。初始化意图先保存，再调用一次 session/new；只有返回准确 H 才就绪。这是启动宿主初始化，不提交 Agent 输入。
- 后续 createSession 才创建不同的实际上下文 A/B。load/start 只允许已有 Courier 所有权映射的上下文；H、未知或空所有权引用在 RPC 前拒绝。
- 宿主初始化的 dispatching/unknown 会阻止对象重建后的重新派发；不把不透明结果当作未创建。
- composeReal 已接入该模式和核对回调。所有权模式进入证据指纹，authentication.js 也进入固定代码摘要；既有证据不会因配置开关自动变得有效。

本记录对应 229 项检查阶段的显式端点/宿主模式。后续已补充自动创建与发现、持久宿主复用和镜像活动归属检查，并接入 composeReal，详见 automatic-runtime-2026-11-06.md；宿主丢失后的自动替换仍未实现。真实 serve 继续受全部能力门槛限制。

先前一次原启动宿主 load 的样本返回匹配标识，但未确认空闲，已停止，未恢复 A；没有把它记为通过。
