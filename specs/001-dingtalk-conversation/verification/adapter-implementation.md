新增显式 --steer-waiting：正常桌面 API 管理原问题答复，独立 ACP 提交补充，复用生产请求映射、steer 和输出关联器。
问题未答期间接收单条补充，约 15 秒观察内未见注入；原问题答复后才观察到注入，直接读取正常提交仍未返回，后续输出包含选项及补充标记，随后原提交明确 end_turn。
这是规格所要求的原任务结束前生效观察；没有把答题前消费或观察窗口长度增加为额外门槛，接收与实际消费仍分别记录。
原问题或字段变化时不提交答案，人工输入仅限指定的合成选项；原始 ACP answer receipt、可执行权限、撤销/恢复及完整 Courier 链路仍未通过。

session/new 的回复若复用已知 Harness 会话标识，适配器现在返回 unknown/protocol_conflict，不覆盖原 Courier 关联；正常恢复接受后也保留已知 Harness 会话标识，不能把服务器返回标识当作创建了独立上下文的充分证据。
另行显式 --acp-owned-run 只在新标识与桌面启动用 Harness 会话不同、首轮任务确认完成后，才进入断连/恢复与上下文检查。

新增 --steer-waiting-twice，在同一原问题仍待答时连续提交两条不同输入/操作 ID 的补充，分别保存接收、消费和原提交未返回的直接观察。

新增 --steer-after-completion，先核对原始 ACP 的目标 Run 输出及正常桌面 end_turn/空闲，再只提交一次旧 Run 控制。实际服务器返回 idle，生产解析为明确未接收；约 5.2 秒、23 次观察中原始事件与桌面历史均未变化，没有消费回执。
输出归属使用到达时保存的原始协议帧，桌面历史用于独立变化比较；两条路径的内容和标识不互相冒充。未知或拒绝不重试，不调用 prompt/队列/新建作为回退；这个局部拒绝结果不证明临近完成的消费时序或无限期无新工作。

新增 --steer-slash，复用正常无工具任务及原 Run 执行前置条件，运行中只提交一次随机合成斜杠文本。服务器明确 steered=false、没有 reason；生产解析为 rejected/steer_rejected，不误归为 idle/stale。
实际原始 ACP/桌面各有 26 个可见帧，均指向原 Run 并包含原标记，没有补充标记、消费或 owner 变化，原任务正常 end_turn。这个拒绝样本没有回退 prompt/队列或重试。
探测同时保留历史重置/外来事件与流缓冲截断的失败事实，完整性异常不能判定任何延续或斜杠拒绝场景通过；真实能力门槛保持不变。

新增 --steer-near-completion，以预设 20 行无工具报告的第 18 行标记及前 17 行编号，限定同一原 Run/逻辑消息的受控后期观察点。

首个样本轨迹触及 2000 行上限，结论保持未通过；后续独立样本保留 2016 行完整脱敏轨迹。默认容量仍 2000，后期探测显式 5000，构造器拒绝超过 10000、非整数或非正容量，截断仍使结论不能通过。

新增 --steer-failure-boundaries，先在已确认运行中的原任务提交一次不同预期 Run 的控制，实际明确 stale 拒绝；重新核对原任务后，以不同输入/操作启动一次正确目标的真实 fetch，随后立即关闭自有 Courier 控制连接，生产 receipt 为 unknown/state_unknown。
