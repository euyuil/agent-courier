# 自有后端退出后的自动恢复

日期：2026-11-06。已登录桌面 WorkBuddy 5.6.2；本次自有运行进程的正常注册元数据确认 CLI 为 2.147.0。沿用 Courier 独占实际用户 Harness 会话、桌面仅提供启动宿主的范围，FR-003/FR-009 原文未改。

## 实现与停止条件

普通自动连接工厂在发现后保存进程身份：PID、内核进程启动时刻及系统启动标识。真实值只进入 Git 外私有状态，不进入普通日志或本记录。后续连接先核对这份身份：

- 仍为同一进程时复用原 H；宿主忙碌、待答或端点不可核实均停止。
- 确认进程已消失、PID 已复用或系统已重启时，保留旧激活操作的 retired 记录，并持久登记一次新的创建意图，再创建空白 H2。
- 读取受限、身份损坏、创建意图中断或创建结果 unknown 时不自动再次创建。旧缓存缺少进程证据时也不能仅凭端点不可达认定进程已退出。
- H2 必须不同于旧 H；只有启动宿主更换，原 A/B 及其 Courier 关联不变。既有 unknown Run 不因此被重放，断连也不会主动关闭桌面后端。

## 预热进程的实际发现缺陷与修复

初始自动替换样本已确认旧进程退出、新 H2 不同且就绪，但严格启动参数发现失败，记录为 unverified。进一步的空白宿主样本没有提交任何 Agent 任务，确认新后端来自预热池：参数含 --prewarm，没有 --session-id；它的正常运行注册记录则准确包含 PID、H2、端点和 CLI 版本。

修复后通过正常 app:getConfigDir 路径元数据定位 sessions 目录，仅打开已经归属的候选进程所对应的单份 PID 注册文件，不遍历账号配置、不读取环境或内存。预热候选须同时满足同用户、已知厂商脚本、预热标记、准确工作目录、注册 PID/宿主一致和进程实际持有的回环监听；工作目录本身不能证明归属。拒绝链接文件、过大文件、外来 PID/宿主/端点及多个候选。

握手后再次核对进程身份及注册归属。probe 的 CLI 版本也重新核对同一活进程和端点；与 ACP 明确版本矛盾或无法确认时不提供版本准入。此前 ACP 初始化未报告版本的事实保留，本次正常运行元数据补充了独立读取路径。未知版本实验配置仍不能借此自动准入。
