# 普通独占组合的连接管理

日期：2026-11-06。桌面 WorkBuddy 5.6.2，正常运行注册元数据确认 CLI 2.147.0。

## 实现

普通 composeReal 在 courier-exclusive 配置下使用 ManagedWorkBuddy，统一实现 HarnessPort。管理连接负责初始化空白宿主 H、创建实际用户上下文；在对应专用连接首次 load 原 A/B 前，正常释放自己的管理连接。各实际 Harness 会话分别保留连接，创建连接的短时串行控制不覆盖 Agent 的运行、steer 或人工答案。自动模式进一步按 Courier 会话隔离后端：探测宿主与实际用户宿主分开，A/B 各自拥有空白启动宿主及后端，桌面仍只负责正常启动。

创建归属、操作签名、原输入标识及各原 Run 的接收/完成事实独立持久保存。操作签名只检查同一 operationId 的参数冲突，不做正文去重；同文不同 inputId 各自保留。已知创建结果先保存再释放管理连接，释放失败不另建用户上下文。早到的原生接收/终态不被迟到回执覆盖；晚接收须匹配原引用，不能覆盖明确拒绝。

运行、创建、加载或配置结果未知时停止，不换建、不抢占、不重放。重建后的执行中/unknown 原 Run 继续占用，只有已确认空闲的原上下文允许重新 load。退出尝试关闭所有本应用连接，并收尾退出期间才建立的连接；不销毁后端或取消任务。

组合能力探测只读；管理连接释放后，认证从实际存活的上下文核实，同时核对产品/CLI 版本。宿主生命周期记录按 Courier 归属分区，实际 Harness 引用、归属及原生证明仍使用实例内唯一索引。缺失/损坏的已知隔离路由停止，不退回共享宿主；先前已有共享宿主的原关联保留，不静默迁移。已确认空闲的原上下文恢复时，先经原 Courier 归属的管理路径核实/激活原后端，再释放管理连接并 load 原引用；只有确认旧进程已结束时才按原运行工厂规则更换该归属的空白宿主。执行中/unknown 的原 Run 不进入此路径。固定宿主配置不能提供该后端隔离能力，继续保持未准入。组合角色、自动/固定策略、隔离策略和实现文件进入证据指纹。可选查询、事件重放及服务端幂等明确 unsupported；必需输出/人工能力继续 unverified，所有平台及 Harness 门槛仍在 Stream 注册前执行。

## 真实文本上下文观察

正式入口 --acp-automatic-managed-text 使用同一生产连接管理类和普通连接工厂，未注入能力通过证据。

| 项目 | 结果 |
| --- | --- |
| A/B 创建 | 两个不同原 Harness 会话，专用连接准备成功 |
| 原始上下文 | A/B 分别保存不同合成标记，准确返回 |
| B 续聊 | 未重述标记仍准确复述，未出现 A 的标记 |
| 私有状态重开 | 关闭全部自有连接及 SQLite，再重建管理对象并打开相同数据库 |
| 原 A 恢复 | load 原 A，准确返回未重述标记，未出现 B 标记 |
| 原 B 恢复 | load 原 B，准确返回未重述标记，未出现 A 标记 |
| 认证 | 管理连接关闭后，存活上下文的正常认证核对成立 |
| 轨迹 | 304 帧，完整且未截断 |
| 执行权限批准、钉钉发送 | 均为 0 |

该阶段的五个文本 Run 对应检查通过，范围为适配器对象重建及私有 SQLite 重开；尚未覆盖真实 Courier 应用进程重启或钉钉用户的整条链路。

## 待答期间的其他上下文

首份 --acp-automatic-managed 样本共 365 帧：A 的精确原生问题核对成功，A 待答期间 B 创建并准确完成自己的标记任务，一次原 A 答案回执明确接收。该样本的全局等待窗口包含 B 的工作，窗口结束前没有观察到 A 的续行和终态，结果保持 unverified，不能据此确定问题根因。

复测给原答案单独 90 秒窗口：B 用时 4486 毫秒；答案 resolved=true、queued=false，但原 prompt 未返回，原问题工具无 completed 结果，432 帧样本仍 unverified。

单个 A 的对照样本通过：343 帧，一次原答案明确接收，2186 毫秒后原 Run end_turn；原生问题工具 completed 的结果包含所选标签且不含另一标签。这将已观察差异收窄到共享后端的上下文交错，尚未确定厂商内部根因。没有修改已安装 Harness 或其全局配置。

自动模式改为每个 Courier 会话独立后端后，430 帧交错样本通过：只读运行记录确认两个不同宿主、两个不同后端进程；A 待答时 B 创建并完成标记任务，随后一次原 A 答案明确接收，1837 毫秒后原 Run end_turn。私有库重开后，原 A/B 各自准确复述未重述的原上下文，未出现另一会话标记。最终正式样本另共 507 帧：两宿主及后端进程不同均由入口明确核对，B 用时 7499 毫秒；原 A 答案后 3293 毫秒 end_turn，原生问题工具 completed 结果包含所选标签、不含另一标签；原问题快照在重开前保存，避免被恢复轮的帧覆盖。重开后原 A/B 与各自宿主/后端均复用成功。该修复仅调整宿主分配与持久路由，未新建替代用户上下文、批准执行权限或修改桌面已有会话。

补齐原 Courier 后端的管理激活恢复路径后，最终代码复核样本为 486 帧，结果 observed：B 在 A 待答期间独立运行，原 A 的一次答案、原生工具结果及原 prompt end_turn 均匹配；答案后续行为用时 2578 毫秒。私有库重开后原 A/B、各自宿主与后端均复用，未重述的上下文准确且没有交叉标记。该样本复用了仍存活的用户后端；按 Courier 分区后的旧后端结束/新宿主组合仍需补充真实观察，不能直接复用先前单宿主恢复结论。

随后已补充 B 待答期间的 A 后端正常结束/原 A 恢复，以及三个独立适配器进程下的原 A/B、仅 A 宿主替换和 B 后端不变。更新结果及边界见 [managed-recovery-2026-11-06.md](managed-recovery-2026-11-06.md)，不等同实际 Courier 应用进程或钉钉整条链路验收。
